# HEARTH app structure (branch `ios-design`)

Five tabs: **Home · Map · Devices · Ready · More**. Phones and the iOS shell open on Home; the welcome chooser is gone there. The classic planner (Compare / Explore / Prepare / Evidence) is still reachable with `?view=planner` on the web and, inside the app, through **More → Planner tools**. Model, data and existing tests are unchanged.

Rule for every screen: one hero, at most three sections before scrolling, one-line copy, details one tap away.

## What each screen shows, and what was cut
- **Home**: greeting, my place (two plan results), my device (temp + sparkline), readiness ring, three quick actions. Cut: scenario controls, KPI cards, the legend, the map, the Christmas Eve paragraph (kept on the place screen), the "check your area / planner" choice.
- **Map**: full-bleed map, floating MW-only | People-first | Changes control, a "92 MW cut · Balanced" pill, and a peek sheet with three stats. Cut: hero title, scenario card, KPI cards, filters row, totals card, legend (now in the sheet), tips disclosure, footer. Scenario and priority controls moved into the pill's sheet. Tap a tract for the zone sheet.
- **Devices**: device rows with a "+" for adding. Device screen: temperature hero, 24 h chart, outage list, cooling rate. Outage detail: duration, six facts, chart. Cut: raw tables, long copy.
- **Ready**: progress ring and four short grouped lists plus "Check on" and Share. Cut: intro paragraphs; setup questions only on first open (three-step sheet).
- **More**: six rows. Planner tools (Explore, Shortlist, Evidence, Methods) are pushed screens, so planners lose nothing; "How HEARTH works" is three one-line rows instead of the methods page.

## Devices and data honesty
- Real data: `data/frozen/device_events.json` and `device_readings.json` (written by `scripts/device_export.py` from the firmware's `EXPORT` output) are bundled by `npm run data:export` into `app.json` as `device`.
- Demo data: when those files are absent the Devices tab shows "Demo device" generated by `web/demo/deviceSample.js` (fixed seed). A "Sample data" badge appears on the device row, device header, Home card, every outage row and every outage detail. Tests fail if any sample surface renders without it, and real data is never mixed with sample data.
- "Connect HEARTH Home" and "Start cooling test" are explained but their buttons read "Coming soon" and are disabled; nothing pretends to pair or to start a test.

## Firmware (`firmware/hearth_node/hearth_node.ino`)
Based on `node_screen.ino` (screen layout code is byte-identical; checked with `diff`). New: every minute it saves last-seen time and temperature to NVS; every 5 minutes it adds a reading to a 24 h ring; on boot a gap longer than 3 minutes between last-seen and the DS3231 clock becomes an outage event (start = last seen, end = now, temp at start, first reading after boot as temp at end). The newest 20 events are kept; a dead coin cell skips detection. Serial `EXPORT` prints JSON lines. Compile check: `arduino-cli compile --fqbn esp32:esp32:adafruit_feather_esp32_v2 firmware/hearth_node`.

## Tests
`web/device.test.js` (outage math, sample determinism, real-over-sample priority), `web/shell.test.js` (checklist), `web/shell-render.test.js` (Home with 0 places / 0 devices / fresh checklist, sample badge on every sample surface, routing), `tests/test_device_export.py` (serial log to JSON).
